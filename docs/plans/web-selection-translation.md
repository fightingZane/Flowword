# 网页划词翻译方案 · 待审核

## 1 项目目标与价值
把FlowWord从视频字幕学习延伸为网页英文阅读工具，面向阅读英文文章、技术文档和网页资料的用户
核心目标是选中英文后，在原位置理解词义或句义，并能收藏、回到原文、进入同一复习系统
成功标准是少打断阅读、首次结果尽早展示、缓存再次打开迅速、来源可追溯；不承诺首次云请求零延迟

## 2 功能需求与边界
| 优先级 | 功能 | 输入 → 处理 → 输出 | 异常 |
| --- | --- | --- | --- |
| P0 | 划词入口 | 选区 → 本地过滤与定位 → 小工具条 | 无文本、过长或输入框不显示 |
| P0 | 翻译 | 用户点击 → 缓存/后台模型 → 中文解释 | 请求失败可重试，选区变更取消旧请求 |
| P0 | 语境释义 | 单词/短语+所在句 → 模型消歧 → 本句中的含义与词性 | 不编造缺失上下文 |
| P0 | 收藏 | 原文+释义+页面信息 → 本地事务 → 已加入 | 保留不同来源的不同含义 |
| P0 | 来源与复习 | 页面URL/标题/原句 → 网页来源分组 → 原文回看与本地复习 | 页面改版时回网页并提供原句查找 |
| P1 | 朗读/快捷键 | 用户动作 → 浏览器语音或复用快捷操作 → 播放/打开 | 没有合适英语声音时明确提示 |
| P1 | 粘贴翻译 | 用户粘贴英文 → 同一翻译服务 → 结果与收藏 | 没有网页来源，标记为手动文本 |
| P2 | 整页双语/段落跟随 | 多段正文 → 分段翻译 → 双语展示 | 成本与排版需另评估 |

第一版限普通网页中可选择的英文文本，建议每次不超过1500字符，超出后请缩小选区；最终上限由验证决定
不做桌面任意软件取词、截图OCR、图片文字、扫描PDF、整页自动翻译和后台全网页扫描；浏览器内置PDF与跨域iframe单独验证，不算默认支持

## 3 用户交互与界面设计
推荐流程：选中英文 → 原选区附近出现「翻译 / 收藏」短工具条 → 点击翻译 → 展开暗绿色小卡片
单词卡片：原词、可选发音、当前语境中文义；详细词义折叠；底部收藏与复制
句段卡片：原文紧跟中文，必要解释折叠；不一次展示大量推荐词，避免遮住正文
默认宽320–420px，遇屏幕边缘翻向内侧；多行选区按靠近鼠标松开位置的矩形定位；卡片支持固定、关闭，点击外部或Esc关闭
点击工具条前先保存原选区，避免按钮导致选区消失；选区变化时旧返回不得替换新结果
不改浏览器自身菜单，不覆盖截图中Kimi菜单；我们绘制独立网页工具条，其他扩展同场显示时可能冲突，可关自动工具条改快捷键
只保留必要按钮和明确错误，不长期显示来源代码、缓存提供方等说明小字

## 4 技术与知识拆解
必须理解：网站授权控制能在哪些页面工作、云请求可能付费、收藏本地保存和备份方式
大致了解：选区就是用户框选文字的范围，定位取该范围的屏幕坐标，缓存复用相同原文与语境
可交AI：DOM选区解析、浮层定位、请求取消、模型结果校验、数据迁移、自动测试
复用React、TypeScript、WXT、现有主题/滚动容器/后台模型服务，不引入独立服务端或新框架

## 5 实现原理与可行性
网页脚本在鼠标松开或键盘选区稳定后，通过Selection读取文字和Range坐标，在Shadow DOM绘制工具条
只在用户点击翻译时发送选中文本与必要所在句，默认不上传URL、标题、整页正文；密钥继续保存在扩展侧
词或短语优先携带所在句；整句直接翻译，邻段仅用户展开时补充，避免无边界上传
后台负责缓存、请求优先级、取消和解析，先展示整句中文，详细解释独立补充；词卡不串行等待整句和多轮模型调用
成熟部分：普通DOM选区、浮层、后台请求与本地收藏。需验证：多行/反向选区、网页Shadow DOM、浏览器缩放、iframe、和其他划词扩展的遮挡
最小实验用普通文章、技术文档、动态网页、长选区/键盘选区等夹具验证，不访问用户隐私页面；通过后再做收藏迁移

## 6 方案比较与架构
| 方式 | 优点 | 代价 | 建议 |
| --- | --- | --- | --- |
| 划选后自动请求翻译 | 少一次点击 | 每次误选可能联网/计费，更干扰阅读 | 以后可独立开启 |
| 划选出现工具条，点击后翻译 | 接近截图，控制调用，阅读不受打扰 | 多一次点击 | 默认采用 |
| 右键菜单或快捷键 | 不挤页面，冲突少 | 入口不如工具条直观，右键需新增contextMenus权限 | 第一版快捷键兜底，右键可P1 |

模块：SelectionAdapter提取选区/语境 → SelectionController明确管理closed/toolbar/loading/ready/error → SelectionCard界面 → 现有后台翻译调度 → 本地统一词本
不要求网页包含video，和视频适配器并列，网页翻译不调用暂停/播放接口
来源不能伪造成零秒视频：设计通用来源kind=video/web/manual；网页保存URL、标题、原句、选中文字及可选位置线索，视频继续保存时间范围
旧视频数据迁移默认video，手动文本无URL；新增来源会涉及数据库与备份版本升级，先写迁移/回滚测试，再接收藏
来源定位优先重新查找原句，文本片段链接只作增强，不保证页面改版后精确定位；正文DOM节点路径不当作唯一身份

## 7 开发阶段
A 可行性夹具：选区、定位、输入区排除、键盘/缩放/滚动，完成标准是不误取文字、不挡选区、无额外网络
B 阅读MVP：工具条/小卡片、语境翻译、缓存取消/重试、每站开关，完成标准是正常和失败流程均可用
C 来源与收藏：通用来源迁移、页面收藏分组和现有复习，完成标准是旧视频完整保留、新网页可备份恢复
D 真实体验：用户选定几个站实测，记录首次/缓存P50与P95及误译案例，再决定自动请求、朗读或整页翻译

## 8 测试与验收
空白/中文/混合/长文本、跨行与反向选区、双击单词、键盘Shift选择、滚动/缩放/边缘定位、页面重排、输入框与密码框排除
取消/反序返回不覆盖、缓存损坏仍展示成功译文、关闭不另发请求、只点击才联网、密钥不进入网页
旧视频收藏迁移前后数量与多语境一致，网页同词不同义独立，来源失效可返回网页，备份和恢复完整，本地复习不调用模型
端到端：授权网页 → 选词 → 查看语境义 → 收藏 → 选句翻译 → 词本按网页找到 → 返回原文 → 复习 → 导出再恢复
验收记录区分模拟接口与真实模型，先记录点击到卡片出现/首条译文/完整结果，不提前承诺具体在线毫秒数

## 9 安装、成本与维护
继续使用同一个浏览器扩展，不另装客户端或服务端；每站授权复用已有机制，更新说明明确网页阅读能力
本地开销主要是选区事件和有界语境抽取，事件合并、关闭时清理监听，不扫描整篇页面
默认划选零网络，点击才请求；长文限制和独立详细解释减少费用，同句同语境缓存，绝不承诺所有提供方失败不计费
复用本地Key、备份和导入导出；提供方失效时可换兼容服务，离线保留已收藏释义和复习

## 10 风险与替代
浏览器受限页面不能正常注入；跨域iframe需额外站点授权，第一版只做顶层，失败时提示复制到粘贴入口
网页禁选/图片无DOM文字则不支持，不暗中截图或OCR；浮层与网站或其他扩展冲突时用快捷键入口
语境提取可能过多或失准，限定到最近完整句与字符上限，实际模型歧义案例再迭代
还需决定：是否首版同时做粘贴入口、朗读是否必要、将来是否要默认自动请求；这些不阻碍推荐MVP先验证

## 11 AI协作与版本规范
此文是方案，本轮不开发划词功能，用户审核后再进入A阶段
主干保留0.6.1可用版本，后续新功能用独立分支分阶段提交；Git提交与推送由用户执行，AI不替用户操作
涉及站点权限、上传内容、数据库/备份格式先写影响说明；不重构视频播放流程，不删原有视频功能
每阶段更新设计、任务、测试报告与变更记录，回滚代码前先备份新格式数据；不将测试假Key或用户资料写进源码

## 12 结论
值得继续，普通网页选区翻译技术可行，也能复用大部分现有翻译和复习能力
推荐「选区小工具条＋点击展开暗绿翻译卡＋必要句级语境＋本地收藏复习」，先做顶层可选择文本
第一阶段只验证选区和定位，避免在文字获取尚未稳定时提前扩展整页翻译、OCR与复杂权限
